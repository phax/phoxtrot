# Regression check (2026-11-16)

`abbc3d3` against `7871700` (the commits before and after the JAXP URNs and secure processing default,
`PhoxtrotTransformer.setCurrentDateTime`, the removal of Apache Xerces-J as schema provider, the `fn:parse-xml` entity
resolver and the Static Typing Feature), measured with `phoxtrot-xslt-benchmark/compare.sh -f 1 -wi 3 -w 2s -i 5 -r 3s
-prof gc -p m_nSize=10000` for the compile, parse, XPath, XSD and XSLT workloads. The workloads with the largest
differences were measured again in the reverse order of the commits with `-f 2 -wi 5 -i 8`.

| Workload | `7871700` | `abbc3d3` | Reverse order (`abbc3d3` / `7871700`) |
|----------|-----------|-----------|---------------------------------------|
| parse | 13.3 ms | 14.0 ms | 13.4 / 14.0 ms |
| XPath child | 0.35 ms | 0.39 ms | 0.38 / 0.39 ms |
| XSLT recursion | 23.4 ms | 24.8 ms | 23.7 / 24.1 ms |
| XSLT serialise json | 11.3 ms | 12.1 ms | 11.4 / 11.1 ms |

Every other workload is within 5 % in the first run. The allocation per operation is the same on both commits for
every workload (within 1 %), and the differences of the first run do not keep their sign in the reverse order: no
regression. The changes touch run-time paths only through an extra field in the run state of `DynamicContext` and the
system ID of `fn:parse-xml`.

The Static Typing Feature only runs when switched on. Compiling eight typical expressions (paths, predicates, `for`,
`let`, function calls, an inline function, map and array constructors) with a declared context item type takes
1.65 µs per expression without and 2.27 µs with it (+0.6 µs); a JFR profile shows no hot spot, the time is spread
over the walk and its small allocations.
